§01 · Number Theory

Chinese Remainder Theorem

Tier 1Every year Solve a system of congruences x ≡ a_i mod m_i when the m_i are pairwise coprime.

The Procedure

  1. Let $M = m_1 \cdot m_2 \cdots m_k$.
  2. For each $i$: compute $M_i = M/m_i$.
  3. For each $i$: find $y_i = M_i^{-1} \bmod m_i$ (the modular inverse).
  4. Answer: $x = \sum_i a_i \cdot M_i \cdot y_i \bmod M$.

Finding $M_i^{-1} \bmod m_i$: just try small numbers $y$ until $M_i \cdot y \equiv 1 \pmod{m_i}$. With small moduli (5, 7, 11), this takes seconds.

Worked Example · Fall 2019

Solve: $x \equiv 1 \pmod 5,\ x \equiv 3 \pmod 7,\ x \equiv 1 \pmod{11}$.

5. $x = 1431 \bmod 385 = 1431 - 3 \cdot 385 = 1431 - 1155 = 276$.
Answer: x = 276

§02 · Number Theory

Fermat's Little Theorem

Tier 1Every year Compute $a^{\text{big}} \bmod p$ when $p$ is prime and $\gcd(a,p)=1$.

The Theorem

If $p$ is prime and $p \nmid a$, then $a^{p-1} \equiv 1 \pmod p$.

The Procedure

  1. Confirm $p$ is prime, $\gcd(a,p)=1$.
  2. Divide the exponent: write $\text{exp} = (p-1) \cdot q + r$ where $0 \le r < p-1$.
  3. Then $a^{\text{exp}} = (a^{p-1})^q \cdot a^r \equiv 1^q \cdot a^r \equiv a^r \pmod p$.
  4. Compute $a^r \bmod p$ directly.

Worked Example · Fall 2019 / Fall 2008

Find $3^{675} \bmod 13$ using Fermat's theorem.
1. 13 is prime, $\gcd(3,13) = 1$. ✓
2. $p - 1 = 12$. Divide: $675 = 12 \cdot 56 + 3$. So remainder $r = 3$.
3. $3^{675} \equiv 3^3 \pmod{13}$.
4. $3^3 = 27 = 2 \cdot 13 + 1 \equiv 1 \pmod{13}$.
Answer: 1 (the exam answer key wrote "27" — same thing, just unreduced)

§03 · Number Theory

Euler's Theorem

Tier 1Every year Generalisation of Fermat for any modulus $n$ when $\gcd(a,n)=1$.

The Theorem

If $\gcd(a,n) = 1$, then $a^{\varphi(n)} \equiv 1 \pmod n$.

The Procedure

  1. Compute $\varphi(n)$ (see §04).
  2. Confirm $\gcd(a,n) = 1$.
  3. Divide: $\text{exp} = \varphi(n) \cdot q + r$.
  4. $a^{\text{exp}} \equiv a^r \pmod n$. Compute.

Worked Example · Fall 2019

Find $7^{483} \bmod 9$.
1. $9 = 3^2$, so $\varphi(9) = 9 - 3 = 6$.
2. $\gcd(7,9) = 1$. ✓
3. $483 = 6 \cdot 80 + 3$. So $7^{483} \equiv 7^3 \pmod 9$.
4. $7^3 = 343 = 38 \cdot 9 + 1 \equiv 1 \pmod 9$.
Answer: 1

§04 · Number Theory

Euler's Totient φ(n)

Tier 1Every year Number of integers in [1, n] coprime to $n$.

The Two Rules

  • If $p$ is prime: $\varphi(p^k) = p^k - p^{k-1}$.
  • If $\gcd(m,n)=1$: $\varphi(mn) = \varphi(m)\varphi(n)$.

The Procedure

  1. Factor $n$ into prime powers: $n = p_1^{e_1} \cdot p_2^{e_2} \cdots$.
  2. Compute each $\varphi(p_i^{e_i}) = p_i^{e_i} - p_i^{e_i - 1}$.
  3. Multiply them all together.

Worked Example · Fall 2019

Find $\varphi(35840)$.
1. Factor: $35840 = 2^{10} \cdot 5 \cdot 7$.
2. $\varphi(2^{10}) = 2^{10} - 2^9 = 1024 - 512 = 512$.
3. $\varphi(5) = 4$, $\varphi(7) = 6$.
4. $\varphi(35840) = 512 \cdot 4 \cdot 6 = 12{,}288$.
Answer: 12,288

§05 · Number Theory

Miller-Rabin Primality Test

Tier 1Every year Probabilistic prime test. Comes in two flavors: count iterations for desired error, or run the test on a small number.

Error Calculation (Easiest version of the question)

Each iteration has at most $1/4$ chance of falsely declaring a composite "prime". After $t$ iterations, error $\le (1/4)^t$.

If asked: "How many iterations for error $\le 1/2^k$?" — solve $(1/4)^t = 1/2^k$ → $t = k/2$.

Examples: error 1/16 → t=2; error 1/64 → t=3; error 1/1024 → t=5.

```

Running the Test on a Number $n$

  1. Write $n - 1 = 2^k \cdot q$ with $q$ odd.
  2. Pick random witness $a$ with $1 < a < n - 1$.
  3. Compute $a^q \bmod n$. If $\equiv 1$ or $\equiv -1 \pmod n$ → "probably prime", stop.
  4. Otherwise: square repeatedly. Compute $a^{2q}, a^{4q}, \ldots, a^{2^{k-1}q}$ all mod $n$.
  5. If any is $\equiv -1 \pmod n$ → "probably prime". If you finish the chain without seeing $-1$ → composite.
```

Worked Example · Fall 2019

How many iterations should the primality test be repeated to get error $\le 1/1024$?
1. $1024 = 2^{10}$. Need $(1/4)^t \le 1/2^{10}$.
2. $(1/4)^t = 1/2^{2t}$. So $2t = 10$ → $t = 5$.
Answer: t = 5

Worked Example · Run the test (Fall 2008)

§07 · Public Key

RSA Encryption / Decryption

Tier 1Every year Given $p, q, e, M$ — encrypt, then verify by decrypting.

Setup

  1. $n = pq$.
  2. $\varphi(n) = (p-1)(q-1)$.
  3. Public key $e$ must satisfy $\gcd(e, \varphi(n)) = 1$.
  4. Private key $d = e^{-1} \bmod \varphi(n)$ (find by extended Euclidean or trial).

Encrypt & Decrypt

  • Encrypt: $C = M^e \bmod n$.
  • Decrypt: $M = C^d \bmod n$.

Tip: For exam-sized problems, find $d$ by inspection. Test small multiples: $1 \cdot e, 2 \cdot e, 3 \cdot e, \ldots$ until one is $\equiv 1 \pmod{\varphi(n)}$.

Worked Example · Fall 2008 (Chehab's favorite numbers)

$p=5, q=13, e=5, M=6$. Encrypt and verify decryption.
1. $n = 5 \cdot 13 = 65$. $\varphi(n) = 4 \cdot 12 = 48$.
2. $\gcd(5,48) = 1$ ✓. Find $d$: $5d \equiv 1 \pmod{48}$. Trial: $5\cdot 29 = 145 = 3 \cdot 48 + 1$. So $d = 29$.
3. Encrypt: $C = 6^5 \bmod 65$. $6^2 = 36$. $6^4 = 36^2 = 1296 \equiv 61$ (since $1296 - 19 \cdot 65 = 1296 - 1235 = 61$). $6^5 = 61 \cdot 6 = 366 \equiv 41 \pmod{65}$.
4. Decrypt: $M = 41^{29} \bmod 65$. Use square-and-multiply ($29 = 11101_2$). After all steps you get back $6$. ✓
C = 41. Decryption recovers M = 6.

RSA Chosen-Ciphertext Attack

Tier 2FA08, FA12 — verbatim repeat Pre-memorize this proof. It's appeared word-for-word in two consecutive years.

The Setup

Bob intercepts ciphertext $C = M^e \bmod n$. He wants $M = C^d \bmod n$ but doesn't have $d$. He tricks Alice into signing a related value.

Bob's procedure

  1. Pick random $r < n$.
  2. Compute $Z = r^e \bmod n$, $X = ZC \bmod n$, $t = r^{-1} \bmod n$.
  3. Send $X$ to Alice. She signs: $Y = X^d \bmod n$.
  4. Bob computes $tY \bmod n$ — and that's $M$.

Why it works

$Y = X^d = (ZC)^d = Z^d \cdot C^d = (r^e)^d \cdot M = r^{ed} \cdot M = r \cdot M \pmod n$ (since $ed \equiv 1 \pmod{\varphi(n)}$).

So $tY = r^{-1} \cdot r \cdot M = M \pmod n$. ✓

Memorize this 3-line argument. The exam asks "show how Bob recovers M". Write the chain $Y \to r^{ed}M \to rM$, then $tY = M$. That's the answer.

Tier 1Every year Given prime $q$, primitive root $\alpha$, and public values $Y_A, Y_B$ — find private keys and shared secret.

Recipe

  • Public: prime $q$, primitive root $\alpha$ of $q$.
  • Alice picks $X_A$, publishes $Y_A = \alpha^{X_A} \bmod q$.
  • Bob picks $X_B$, publishes $Y_B = \alpha^{X_B} \bmod q$.

§13 · Symmetric

Block Cipher Modes of Operation

Tier 2FA12 P14 (CBC variant) Know each mode's structure, error propagation, and security properties.

The Five Modes

  • ECB — Electronic Codebook. $C_i = E_K(P_i)$. No chaining. Identical blocks → identical ciphertext (security disaster). Used: secure transmission of single value.
  • CBC — Cipher Block Chaining. $C_i = E_K(P_i \oplus C_{i-1})$, $C_0 = \text{IV}$. Hides patterns. Authentication possible. Error in $C_i$ corrupts $P_i$ and $P_{i+1}$ on decryption.
  • CFB — Cipher Feedback. Stream-style. $C_i = P_i \oplus E_K(C_{i-1})$. Self-synchronizing. Good for stream of small bits.
  • OFB — Output Feedback. Generates keystream independent of plaintext: $O_i = E_K(O_{i-1})$, $C_i = P_i \oplus O_i$. No error propagation in plaintext. Sensitive to bit flips ⇒ same bit flip in plaintext.
  • CTR — Counter. $C_i = P_i \oplus E_K(\text{nonce} \| i)$. Parallel. No chaining. Nonce must never repeat.

Common exam variants

"Show that CBC encryption can detect tampering if last block known", "draw OFB diagram", "explain why ECB leaks structure". Memorize the 5 diagrams + 5 one-line security comments.

Quick test: If a single ciphertext bit is flipped in transit, in which mode does the error stay confined to one block of plaintext during decryption? OFB and CTR (single-bit flip in plaintext bit). CBC: corrupts the current block fully + 1 bit of the next. CFB: corrupts the current block + a partial of the next.

Show answer
Identical plaintext blocks produce identical ciphertext blocks. Visually structured plaintexts (logos, text on uniform background) leave their structure visible in the ciphertext — the famous "ECB penguin" demonstration.

P3. Why does CTR mode require a unique nonce per encryption (never reuse)?
Show answer
If two messages use the same nonce + counter sequence, the same keystream is generated. XOR-ing the two ciphertexts cancels the keystream, leaving $P_1 \oplus P_2$ — directly leaks plaintext relationship and often enables full plaintext recovery from known plaintext or statistical attacks. Same flaw as reusing a one-time pad.
P4. Which modes allow random-access decryption (decrypt block $i$ without decrypting blocks $0..i-1$)?
Show answer

CTR: Same as OFB — single bit flip in $P_i$, no propagation.

CBC binds blocks together, so swap/splice changes the next block's decryption, which is at least detectable as garbage.

AES Key Expansion

Tier 3FA19 only Generate W[0..43] from the original 16-byte key. Exam asks W[4..7] and W[8..11].

Procedure

  1. Original key fills $W[0], W[1], W[2], W[3]$ (each $W[i]$ is 4 bytes).
  2. For $i = 4, 5, \ldots, 43$:
    • $\text{temp} = W[i-1]$.
    • If $i \bmod 4 = 0$: $\text{temp} = \text{SubWord}(\text{RotWord}(\text{temp})) \oplus \text{Rcon}[i/4]$.
    • $W[i] = W[i-4] \oplus \text{temp}$.

RotWord: cyclic left rotation by 1 byte. SubWord: apply S-Box to each byte. Rcon[1..10] = 01, 02, 04, 08, 10, 20, 40, 80, 1B, 36 (all in hex, with the value placed in the leftmost byte and 00 in the other three).

Worked Example · Fall 2019 style

All original key bytes are 0x45. Compute W[4].
1. $W[0] = W[1] = W[2] = W[3] = (45, 45, 45, 45)$.
2. $i=4$: $\text{temp} = W[3] = (45,45,45,45)$. RotWord → $(45,45,45,45)$ (all equal, unchanged). SubWord → $(\text{S-Box}[45], \ldots) = (6E, 6E, 6E, 6E)$. XOR Rcon[1] = (01,00,00,00) → $(6F, 6E, 6E, 6E)$.
3. $W[4] = W[0] \oplus \text{temp} = (45,45,45,45) \oplus (6F,6E,6E,6E) = (2A, 2B, 2B, 2B)$.
W[4] = (2A, 2B, 2B, 2B). Then W[5] = W[1] ⊕ W[4], W[6] = W[2] ⊕ W[5], W[7] = W[3] ⊕ W[6].
Speed tip: When the original key has all identical bytes, RotWord is the identity and W[5..7] propagate as simple XOR cascades. Most of the work is the single S-Box lookup at i=4 and i=8.

§16 · Auth

Hash Functions & MAC

Tier 2FA19 P18 Properties, HMAC structure, and the recurring "scheme analysis" question.

Hash function security properties (in increasing strength)

  1. Preimage resistance: given $h$, hard to find $m$ with $H(m) = h$.
  2. Second-preimage resistance: given $m$, hard to find $m' \ne m$ with $H(m') = H(m)$.
  3. Collision resistance: hard to find any $m \ne m'$ with $H(m) = H(m')$.

For an $n$-bit hash: brute-force preimage $\approx 2^n$. Brute-force collision $\approx 2^{n/2}$ (birthday).

```

HMAC Construction

$\text{HMAC}(K, M) = H((K \oplus \text{opad}) \,\|\, H((K \oplus \text{ipad}) \,\|\, M))$ where opad = 0x5c repeated, ipad = 0x36 repeated. Two passes through hash $H$. Key needs to be padded to block length.

MAC vs Encryption order

  • Encrypt-then-MAC: best. Reject ciphertext before decrypting → resistant to chosen-ciphertext attacks.
  • MAC-then-Encrypt: weaker. Used in TLS < 1.3 and SSL — caused real attacks.
  • Encrypt-and-MAC: weakest. MAC may leak info about plaintext.

The "scheme analysis" question (FA19 P18 / IMG hint)

Examiner gives a hash/MAC/auth scheme and asks: "is it secure?" or "what does the receiver do to verify?". Method: trace each step. Look for missing nonces, missing IVs, unsigned values, replays, length-extension exposure (vanilla Merkle-Damgård).

P2. Why is "encrypt-then-MAC" preferred over "MAC-then-encrypt"?
Show answer
The receiver can verify the MAC before decrypting. If the MAC fails, decryption never runs — preventing chosen-ciphertext oracles. With MAC-then-encrypt, you must decrypt first to see the MAC, and the decryption itself can leak information through padding errors etc. (the basis of the BEAST/Lucky-13 family of attacks).

P5. What does a MAC provide that a plain hash function does not?
Show answer
A MAC requires a shared secret key. This provides authentication — only someone with the key can produce a valid tag, so the receiver knows the message came from someone with the key. A plain hash provides only integrity against accidental corruption (anyone can recompute it on a tampered message).
P6. Why does HMAC use two passes through the hash function (with ipad/opad)?
Show answer
Defends against length-extension attacks. A naive MAC = $H(K \| M)$ is broken: an attacker can extend $M$ to $M \| \text{padding} \| M'$ and compute the new MAC without knowing $K$, thanks to Merkle-Damgård's iterative structure. The double-hash construction $H(K_o \| H(K_i \| M))$ wraps the inner hash output, blocking the extension.

Show answer
Birthday attack territory. With $2^{n/2} = 2^{32}$ samples, collision probability becomes ~50%. At $2^{40}$ they almost certainly have collisions. If the attacker can submit chosen messages or get arbitrary MACs, this is catastrophic. 64-bit MACs are too short for serious systems — modern designs use 128 bits or more.

Schnorr-style Discrete-Log Proof

Tier 2FA08 P13, FA12 P13 "What does Victor check?" The recurring zero-knowledge problem.

Setup

Public: prime $p$, generator $g$, $y = g^s \bmod p$. Secret: $s$ (Peggy/Alice knows it).

Protocol

  1. Peggy picks random $k$, sends $\gamma = g^k \bmod p$ to Victor.
  2. Victor sends random challenge $r$.
  3. Peggy sends $z = k - sr \bmod (p-1)$.
  4. Victor checks: does $\gamma \equiv g^z \cdot y^r \pmod p$?

Why it works

$g^z \cdot y^r = g^{k-sr} \cdot g^{sr} = g^k = \gamma$. Knowing $s$ allows Peggy to produce a valid $z$. Without $s$, she'd have to guess $r$ before committing $\gamma$, which has negligible chance.

Memorize the equation: $\gamma \equiv g^z \cdot y^r \pmod p$. That is the answer to "what does Victor check?". Show the algebra of why it equals $\gamma$ when $z = k - sr$.

Your Turn

P1. Suppose Peggy doesn't know $s$ and tries to cheat. After committing $\gamma$, what's the probability she can produce a valid $z$ for an arbitrary random $r$ chosen by Victor?
Show answer
Negligible — at most $1/(p-1)$ per round. To cheat, she'd have to guess $r$ before committing $\gamma$. Each round repeated → exponentially small probability.
```
P2. Why must Peggy use a fresh random $k$ each session? What goes wrong if she reuses $k$?
Show answer
Catastrophic. If she reuses $k$, an attacker observing two transcripts $(\gamma, r_1, z_1)$ and $(\gamma, r_2, z_2)$ recovers $s$:
$z_1 - z_2 = (k - sr_1) - (k - sr_2) = s(r_2 - r_1) \pmod{p-1}$
So $s = (z_1 - z_2) \cdot (r_2 - r_1)^{-1} \pmod{p-1}$.
Same trap that broke the Sony PS3's ECDSA implementation in 2010.
P3. What property does this protocol have that "send $s$ directly" does not?
Show answer
Zero-knowledge. Peggy proves possession of $s$ without revealing any information about $s$ — Victor learns only that Peggy knows the discrete log of $y$. Repeating the protocol gives Victor confidence but never reveals $s$.

§18 · Cheatsheet

Problem 1 — Conceptual Short Answers

Tier 1Every year, ~20 points The professor's recurring concept block. Short, crisp answers win.

The Standard Question Bank

Q · Number of keys for N users

Symmetric: each pair shares one secret key → $\binom{N}{2} = \frac{N(N-1)}{2}$ keys total.
Public-key: each user has 1 public + 1 private = $2N$ keys total. Massive scaling advantage.

Q · Why use a nonce?

To prevent replay attacks. The nonce ties a message to a specific session/instance, so an attacker can't re-send a captured authentic message and have it accepted again.

Q · Limitation of timestamps

Requires synchronized clocks across parties. Clock drift, network delay, and time-zone differences create a window where (a) legitimate messages get rejected as stale, or (b) attackers can replay within the tolerance window. Hard to maintain in a distributed system.

Q · Encrypt before or after compression?

Compress before encrypting. Encrypted data is essentially random-looking → it doesn't compress at all. So you must compress while plaintext still has redundancy.

Q · MAC then encrypt, or encrypt then MAC?

Best: Encrypt-then-MAC. The MAC covers the ciphertext, so receiver verifies authenticity before decrypting → no chosen-ciphertext oracle. Used in IPsec, SSH, TLS 1.3.

Q · PGP — confidential + authenticated email

Alice signs her message with her private key (authentication), then encrypts the result with Bob's public key (confidentiality). Bob decrypts with his private key, then verifies signature with Alice's public key.

Q · PGP trust model

Web of trust. No central authority. Each user maintains a keyring with trust ratings: each public key is signed by other users; trust in a key is computed from the signatures' trust levels (full / marginal / none).

Q · SSL — services and protocols

Services: confidentiality (symmetric encryption), message integrity (MAC), peer authentication (typically server-only via certificates), and replay protection (sequence numbers).
Protocols: Handshake, Change Cipher Spec, Alert, and Record protocols.
Shared secrets between peers: typically 6 — for each direction (client→server, server→client): one MAC secret, one encryption key, one IV. (Some textbooks count 4 if IV isn't separate.)

Q · Fiat-Shamir cheating probability

Simplified Fiat-Shamir: cheater succeeds with probability $1/2$ per round. After $t$ rounds: $1/2^t$. The full Fiat-Shamir uses $k$ secrets in parallel → $1/2^k$ per round.

Q · Square-root commitment — proving the commitment was wrong

Reveal the square root. If the committer claimed $c = x^2 \bmod n$ and now claims a different $x'$ also satisfies $c = x'^2 \bmod n$, then $x \ne \pm x' \pmod n$ exposes a non-trivial square root, which factors $n$ — proving inconsistency.

Q · Homomorphic commitment / encryption

Allows operations on ciphertexts that translate to operations on plaintexts. Example: ElGamal is multiplicatively homomorphic: $E(M_1) \cdot E(M_2) = E(M_1 M_2)$. Application: secret-ballot voting (sum encrypted votes without decrypting individuals).

Self-Quiz

Cover the right side. Answer each, then check.
How many keys for 100 users with symmetric encryption?
$\binom{100}{2} = 4950$.
What does the receiver do in a digital signature scheme using RSA?
Compute $V = S^e \bmod n$ from sender's signature $S$ using sender's public key. Compare $V$ to a fresh hash of the message. Equal → valid.
Why is collision resistance harder than preimage resistance?
Birthday paradox. For an $n$-bit hash, preimage takes $2^n$ attempts but collision takes only $2^{n/2}$.
Difference between authentication and integrity?
Integrity: data wasn't modified. Authentication: data came from a specific identified source. A MAC provides both. A plain hash (with no key) provides integrity only against accidental change, not malicious tampering.
Forward secrecy — what is it?
Compromise of a long-term key does not compromise past session keys. Achieved by ephemeral DH at each session.
How many keys for 50 users with public-key encryption?
$2N = 100$ keys total (each user has one public + one private). Compare to $\binom{50}{2} = 1225$ for symmetric. The scaling difference is the killer argument for public key.
What is the goal of a chosen-plaintext attack?
The attacker can encrypt arbitrary plaintexts of their choice (using the encryption oracle, e.g. Alice's public key in RSA) and use the resulting ciphertexts to deduce something about the key, the cipher's structure, or another target ciphertext's plaintext. Pure RSA without padding is vulnerable; padding schemes like OAEP defend against this.
Why is "textbook RSA" (no padding) insecure even though factoring $n$ is hard?
Several reasons. Deterministic: same M always gives same C → leak through chosen-plaintext. Multiplicatively homomorphic: $E(M_1) \cdot E(M_2) = E(M_1 M_2)$ enables chosen-ciphertext attacks. Small-message attacks: if $M^e < n$, ciphertext is just $M^e$ and you can take the integer $e$-th root. OAEP padding fixes all of these.
Difference between a digital signature and a MAC?
MAC uses a shared symmetric key — both parties can produce and verify, so neither can prove which one made the tag (no non-repudiation). Digital signature uses asymmetric keys — only the holder of the private key can sign, but anyone with the public key can verify. Provides non-repudiation: signer cannot later deny signing.
What is a man-in-the-middle attack on plain Diffie-Hellman?
Eve intercepts both sides. She sends her own $Y_E$ to Alice (pretending to be Bob) and to Bob (pretending to be Alice). She establishes one shared key with each. She can read and re-encrypt all traffic. Defeated by authenticated DH — sign the public values with long-term keys, or use a station-to-station protocol with certificates.
What is the discrete logarithm problem?
Given prime $p$, generator $g$, and $y = g^x \bmod p$, find $x$. No efficient classical algorithm is known for large $p$. Hardness underpins DH, ElGamal, DSA, Schnorr. Shor's algorithm breaks it on a quantum computer.
SSL handshake — what gets exchanged?
1) ClientHello (proposed cipher suites, random nonce). 2) ServerHello (chosen suite, server random, server certificate, server key exchange if needed). 3) Client verifies cert, generates pre-master secret, encrypts with server's public key. 4) Both derive master secret + session keys from pre-master + nonces. 5) ChangeCipherSpec + Finished messages confirm both sides have the keys.
What are the 6 secrets shared between two SSL peers?
For each direction (client→server and server→client): MAC secret, encryption key, IV. Total: 6. These are derived from the master secret using a key-derivation function and the client/server random nonces.
